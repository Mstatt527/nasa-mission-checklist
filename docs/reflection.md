# Reflection

## What I learned

GitHub worked better as the plan than as a place to upload a finished file. Writing the task list as issues first made the pieces obvious: a screen, lanes, a count, and a saved file. Feature branches kept each of those separate, and the pull request was the moment a piece was actually done.

## What was challenging

Keeping the commits small was harder than the app. It was tempting to build the whole task list and commit it once. Splitting the screen, the lanes, the filter, and the save into their own commits took more care than the Python.

## What was fun

The useful moment was adding a step, marking it done, refreshing the page, and seeing it still there. The list is small, but it behaves like a list the crew can actually change.

## What I would improve

With more time I would add a second routine, such as a landing list, and keep a separate list for each person. I would also ask a partner to review the pull requests instead of merging them alone.
